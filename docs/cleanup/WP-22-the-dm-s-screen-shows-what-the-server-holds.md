# WP-22 · The DM's screen shows what the server holds

Part of the [Atlas cleanup list](README.md) — **second pass** (2026-09-26).

**Goal:** The workspace should pick up changes made by players, the Forge and other tabs. A stale field or a late reply should never write old text over newer text, and things the server still holds, such as an unplaced node or a lit lantern, should show correctly and be reachable.

**Do after:** [WP-02](WP-02-protect-the-live-campaign-data-undo-clone-and-ba.md), [WP-03](WP-03-autosave-that-tells-the-truth.md)

**Notes:** Order matters. Fix B096 (compare each blur field with the value it was seeded with, and reseed fields that are not focused) and B095 (re-key or reseed the inspector after forgeRefresh) first. Only then add P101's background refresh or B027's refetch-on-focus: every refresh makes a box the DM has typed in go stale, and a bare click out then writes the old text back. P101 should also refresh the world row (canon, eras, lantern), call flushSave() first, and carry B029's staleness guard. B099 and B028 touch the same setLifespan path, so build one per-placement pending patch that sends only the bound that changed. B097 is the patchMap .then that B029's guard misses. B098 restores worlds.spotlight_node_id on undo, which B008's column lists cannot reach. P102 adds a node-only inspector for unplaced nodes and a remove control for orphaned interiors. C093 stops reporting a failed lookup as 'not placed'. Borders WP-03: that package makes writes reach the server; this one stops the screen from holding and resending stale values.
