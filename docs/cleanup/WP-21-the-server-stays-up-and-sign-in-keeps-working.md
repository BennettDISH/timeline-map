# WP-21 · The server stays up and sign-in keeps working

Part of the [Atlas cleanup list](README.md) — **second pass** (2026-09-26).

**Goal:** A database restart or a Waypoint profile change should not take the app down or lock anyone out. Signing up on Waypoint should not give anyone another person's local account. Fix the smaller server faults found next to these.

**Notes:** Do B090 first. The fix is small: drop process.exit in database.js and add a withTx helper at the six pool.connect() sites. Today an ordinary Postgres restart takes down the DM workspace and every player's phone until Railway restarts the container. B091 is the profile-sync UPDATE: give it the same collision handling account creation uses (freeUsername/freeEmail with the user's own row excepted) and widen users.username/email to Waypoint's widths. B092 is a security fix that changes how pre-SSO rows are linked, so decide it with Bennett; C018's admin-by-central-id (WP-16) closes only the admin half of it. B093 goes away if O014 deletes setup.js. B094 extends B081 (WP-01) to the marker endpoint, where a non-canonical map id writes half a marker. P100 keeps base64_data out of list and ownership queries. P099 gives the ErrorBoundary a reset and an exit. Borders WP-16 and WP-01; kept separate because the first pass never ran real SSO sign-ins or a database drop.
